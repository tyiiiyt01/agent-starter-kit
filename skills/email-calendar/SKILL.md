# 邮件与日程管理

## 0. 先说实话（重要）

这个领域**没有「粘贴一下就能用」的通用免费方案**。多数便捷方案都要**凭证 / 授权 / 企业管理员权限**。下面每个方案都标了门槛，先看清再动手，**别让用户白折腾**。

**总原则**：

- **不要让 AI 自动收发邮件**。发信前**必须人工确认收件人与正文**
- 拿不到凭证时走**降级方案**（起草 + 人工发送、生成 .ics 手动导入），比硬接协议更稳

## 1. 邮件：IMAP / SMTP MCP

真实的通用方案是社区做的 **IMAP/SMTP MCP server**（例如 `classic-imap-smtp-mcp`）。接入条件：

⚠️ **必须用户自己在邮箱里开 IMAP，并用「应用专用密码」**：

- **不能用邮箱主密码**（主密码登录会被拒或触发风控）
- 要先去邮箱网页版**开启 IMAP/SMTP 服务**，再**单独生成应用专用密码**
- **国内邮箱开关位置各不相同**：163、QQ 邮箱、企业邮箱各自的 IMAP 设置入口不一样，要在对应邮箱的「设置 → 账户 / POP3-SMTP-IMAP」里找，**先确认再操作**

配置一般需要：服务器地址、端口、账号、应用专用密码（服务器与端口**以邮箱官方说明为准**）。

## 2. 日历

| 方案 | 门槛 |
|---|---|
| **Google Calendar 官方 MCP** | 需在 Google Cloud 建项目 + OAuth 授权，流程较长 |
| **CalDAV MCP**（如 `dominik1001/caldav-mcp`） | 支持 CalDAV 的日历都能用，需日历地址 + 账号凭证 |
| **国内日历（飞书 / 钉钉 / 企微）官方 MCP** | ⚠️ **需要企业凭证，个人用户基本拿不到** |

## 3. 飞书 / 钉钉 / 企业微信（重点说明限制）

三家都有官方 MCP 或 CLI：

- 飞书：`open.feishu.cn`
- 钉钉：`mcp.dingtalk.com`
- 企业微信：`developer.work.weixin.qq.com`

⚠️ **共同门槛**：接入**需要企业管理员权限去创建应用、拿到 App ID / Secret 等凭证**。**个人用户（没有企业管理员配合）走不通**，不要在这上面耗时间。若所在企业有管理员，才让对方协助开应用。

## 4. 没有凭证时的降级方案（最实用）

做不到自动化，就做「**AI 出内容，人来执行**」：

### 4.1 邮件：AI 起草，人工发送

- 让 AI 按你的语气和目的**写好邮件**（收件人、主题、正文、附件清单）
- 你**复制到邮箱客户端手动发送**
- 好处：安全、零配置；代价：不能批量自动发

### 4.2 日程：生成 .ics 文件，双击导入

`.ics` 是标准日历文件，**双击就能导入** Outlook / Google / Apple 日历。最小合法示例：

```
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//agent-setup-kit//CN
BEGIN:VEVENT
UID:20261012-001@local
DTSTAMP:20261012T090000Z
DTSTART:20261012T140000Z
DTEND:20261012T150000Z
SUMMARY:项目评审会
LOCATION:3 楼会议室
DESCRIPTION:审阅 Q4 方案
END:VEVENT
END:VCALENDAR
```

要点：

- 时间用 **UTC**（结尾 `Z`），或写带时区偏移；北京时间 14:00 对应 `T060000Z`
- `UID` 每条唯一，否则导入时会互相覆盖
- 多个日程就在中间**重复 `BEGIN:VEVENT ... END:VEVENT`** 块
- 文件名用 `.ics` 后缀，用户双击即可导入

### 4.3 日报 / 周报：AI 按模板整理，人工提交

- 把当天零散记录交给 AI，按固定模板（今日完成 / 进行中 / 风险 / 明日计划）整理
- 输出纯文本 / Markdown，用户**手动贴到系统里提交**

## 5. 常见坑自检

- [ ] 已如实告知该方案**需要什么凭证 / 权限**，没有夸大
- [ ] 邮件**没有自动发送**，发送前人工确认过
- [ ] 国内邮箱示例用的是**应用专用密码**，不是主密码
- [ ] 企业类（飞书/钉钉/企微）已说明**需企业管理员**
- [ ] `.ics` 时间用了 UTC 或正确偏移，`UID` 唯一
- [ ] 拿不到凭证时，用户清楚**降级方案怎么走**
