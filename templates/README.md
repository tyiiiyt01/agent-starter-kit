# templates/ —— 两个必配项的模板

这里的两个模板对应新手配置 AI 助手时**共识度最高**的两件事：一份项目说明（AGENTS.md）和一个权限白名单（`.claude/settings.json`）。它们跟宿主无关，任何项目都能用。

> 说明：`.json` 文件里不能写 `//` 注释（写了会导致解析失败），所以 settings 模板的用法与规则**全部写在这份 README 里**，模板本身保持纯 JSON。

---

## 1. `AGENTS.md.template` —— 给「你的项目」的项目说明

**它是什么**：一份放进项目根目录、告诉 AI「这个项目怎么跑、怎么改、什么不能碰」的说明书。Claude Code / Cursor / Trae 等官方都认，`agents.md` 官方站称已有 60k+ 项目采用，并由 Linux 基金会下的 Agentic AI Foundation 治理 —— 是当前共识度最高的必配项。

**怎么用**：
1. 把这个模板交给你的 AI 助手，让它读开头的注释、**探测你的项目**（语言、命令、目录结构），再生成一份定制化的 `AGENTS.md`。
2. 把 `{{...}}` 占位符填成真实内容（命令、路径、约定）。填不出的先留空，让助手补齐后再核对。
3. 放到项目根目录，命名 `AGENTS.md`。Claude Code 也认同源的 `CLAUDE.md`，二者规范一致，选一个即可。

**长度怎么把握**（口径有分歧，按下面来）：
- 主流建议：最小 30 行、推荐 60–100 行、**不超过 200 行**。
- Cursor 官方说「500 行以内」；但社区共识是**越短越好**——长文档会稀释 AI 的注意力，而且很容易和代码重复。
- 本模板默认压在 **60 行以内**。原则只有一条：**只写「从代码里读不出来的信息」，引用文件路径，不要复制代码**。代码会变，复制进文档只会过时。

**新手的常见坑**：写太长、写废话、把实现细节抄一遍。文档越长，AI 越可能忽略其中真正重要的那几条「禁止事项」。

## 2. `claude-settings.json.template` —— Claude Code 的权限白名单

**它是什么**：Claude Code 的 `.claude/settings.json`。官方推荐做法是**用 `allow`/`deny` 白名单预授权安全命令**，而不是图省事用 `--dangerously-skip-permissions`（后者是新手第二大误区）。

**怎么用**：
1. 复制到项目的 `.claude/settings.json`（没有 `.claude/` 目录就新建）。
2. 按你的项目改：`allow` 里的命令名要和项目实际用的工具对上（npm / pnpm / pytest / uv…）。
3. 也可以在 `~/.claude/settings.json` 放一份用户级默认。

**关键规则**：
- **`deny` 优先级高于 `allow`**。两者都命中时，以 `deny` 为准 —— 所以把「绝对不能做」的东西放进 `deny` 是安全兜底。
- 权限语法是 `工具(模式)` 形式：
  - `Bash(git diff:*)` —— 冒号加 `*` 是**前缀匹配**，即允许 `git diff` 开头的所有命令。
  - `Bash(git status)` —— 不带 `:*` 表示**精确匹配**这一条命令。
  - `Read(./.env)` / `Read(./**/credentials.json)` —— 用路径模式（glob）匹配文件读取。
- 本模板的两条硬要求：
  - `deny` 里**必须屏蔽密钥文件**：`.env`、`.env.*`、`credentials.json`、`secrets.json`、`*.pem`、`id_rsa*` 等。
  - `deny` 里加入危险操作：`rm -rf`、`git push --force` / `-f`、`sudo`、`chmod 777`。
- 模板里的具体条目是**示例**，不是标准答案：请按你项目实际使用的命令增删，别直接照抄到不匹配的工具链上（比如你用的是 pnpm，就改成 `Bash(pnpm run test:*)`）。

## 为什么 statusline / hooks 不在这里

`statusLine`（状态栏）和 `hooks`（在工具调用前后自动跑脚本）属于**进阶可选项**，不适合做默认模板：

- **statusLine** 只是显示层面的个性化（比如在状态栏显示分支/模型），不影响 AI 行为，装不装都行。
- **hooks** 会在你的编辑/命令前后**自动执行脚本**，一旦配错就可能拦掉正常操作、甚至误跑命令。它需要用户清楚自己项目的构建/测试流程后再定制，属于「懂了再开」。

所以这两个保持可选：等基础的项目说明（AGENTS.md）和权限白名单（settings.json）跑顺了，再按官方文档按需添加。
